# DOAR V2 rule audit

Source of truth for every table below: `src/doar/rule_schema.py`
(`RULE_PROVENANCE`, `REQUIRED_FEATURE_IDS`, `load_rules_v2()`) and
`resources/psychology_sources/rules_registry.json`. Machine-readable
companion: `artifacts/rule_feature_matrix.csv` (generated by
`scripts/generate_rule_feature_matrix.py` from the same source — do not
hand-edit either; regenerate).

**Total rules found: 19.** All 19 come from exactly one source: a
2-page, non-clinical, non-peer-reviewed Arabic notes document
(`التحليل النفسي للصور.pdf`), explicitly marked
`"scientifically_validated": false` in the registry's own `source`
block. There is no second rule source anywhere in the live pipeline.
(`legacy/src/psychological_rules_v2.py` contains a separate, unrelated
rule set — see `docs/DOAR_V2_MIGRATION.md`; it is isolated legacy code,
not evaluated by any current path, and out of scope for this count.)

Every current rule is `tier_1_prompt_independent` (6 rules, size/

**`tier_3_prompt_or_age_dependent` exists as a category in the schema

`tier_3`. That means age/task/narrative gating in this milestone's
`ontology/context.py`/`engine.py::_context_gate` is currently exercised
only by tests with synthetic rules (`tests/test_ontology_rule_engine.py`),
not by any of the 19 production rules — an honest gap, not a hidden one.

## 2. Framework classification (EMPIRICAL_EXPRESSIVE vs. CLASSICAL_PROJECTIVE)

**All 19 rules are CLASSICAL_PROJECTIVE.** None qualifies as
EMPIRICAL_EXPRESSIVE. This is not a judgment call made for this audit —
it follows directly from the registry's own `scientific_support` field,
which for every rule reads one of: `not_found_for_specific_claim`,
`not_found_for_combined_claim`, `not_found_for_personality_claim`,
`not_found_for_threshold_claim`, `indirect_expression_research_only`,
`indirect_size_research_conflicting`,
`indirect_size_research_does_not_validate_claim`, or
`placement_effects_weak_not_specific`. Several rules (the 6 size/
placement ones) cite real, checkable literature
(`REF_SIZE_2004`, `REF_SIZE_DEPTH_2013`, `REF_PLACEMENT_1992`,
`REF_EYES_EXPRESSION_2007`) — but that literature is cited to show the
folk claim is **not** supported (weak/conflicting/task-dependent
effects), not to support it. Citing a real study against a claim does
not make the claim empirically supported. `ontology/legacy_adapters.py`
enforces this mechanically: `Rule.__post_init__` raises if any rule
claims `EMPIRICAL_EXPRESSIVE` without a real (non-`TODO`) citation, and
`legacy_rule_to_ontology_rule` always tags the converted rule
`CLASSICAL_PROJECTIVE` — verified by
`tests/test_ontology_legacy_adapters.py::test_every_converted_rule_is_classical_projective`.

**No EMPIRICAL_EXPRESSIVE rule exists in this codebase as of this
milestone.** Populating that category (per Section 3's future scope,
item 4 in the task's own list of deferred work — "Freud/Machover/Hammer
rule expansion from external books") is explicitly out of scope here.

**Real ambiguity this reveals:** even if a face/eye detector, an animal
classifier, or a symbol classifier were built exactly as currently
specified, the current `REQUIRED_FEATURE_IDS` mapping could not
distinguish *which* rule should fire — `semantic.face.eyes` collapses
"wide", "stern", and "closed" into one feature_id with no sub-value
schema; `semantic.object.symbol` collapses "stars", "flowers/clouds/sun",
and "hearts" the same way. **Any future detector-building work must
first widen these to categorical features with the specific sub-values
as `allowed_values`** (this milestone's `config/feature_ontology.yaml`
already models `semantic.face.eyes` and `semantic.object.symbol` this
way, as categorical features with `allowed_values`, precisely to make
this fixable without another schema change — see Section 5).

## 5. What this milestone's ontology layer changes (and doesn't)

- Every rule above is now also expressible as a declarative
  `ontology.rule.Rule` with a composable `premise`
  (`ontology/legacy_adapters.py::legacy_rule_to_ontology_rule`), not a
  hand-coded `if` branch. `PSY_AR_SIZE_HALF_014`'s range check
  (`0.40 <= coverage <= 0.60`) is now literally `AllOf(gte 0.40, lte
  0.60)` instead of Python comparison logic duplicated across
  `rules.py` and `evidence_rule_engine.py`.
- The 13 tier-2 rules still cannot fire — no detector exists — but they
  now resolve through the same general three-valued engine
  (`NOT_ASSESSABLE`, never `NOT_MATCHED`) instead of a bespoke
  `missing_detector` status string, verified in
  `tests/test_ontology_legacy_adapters.py::test_tier2_rules_never_matched_or_not_matched`.
- No rule's citation, wording, confidence ceiling, or threshold was
  changed by this migration. `evidence_rule_engine.py`/`rules.py` remain
  the live, unmodified paths; the ontology layer is an additional,
  independently-tested re-expression, not a replacement.

## 6. REVIEW_REQUIRED

None of the 19 rules required a `REVIEW_REQUIRED` flag — every rule's
tier, threshold provenance, and required feature mapping was already
fully documented in `rule_schema.py`'s `RULE_PROVENANCE`/
`REQUIRED_FEATURE_IDS` before this audit, and this audit cross-checked
rather than re-derived that data. If a 20th rule is ever added to
`resources/psychology_sources/rules_registry.json` without a
corresponding entry in both of those dictionaries,
`rule_schema.py::load_rules_v2()` raises immediately (see its own
`ValueError` checks) — the registry cannot silently grow ahead of its
own provenance/audit trail.
